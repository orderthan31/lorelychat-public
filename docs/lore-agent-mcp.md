# Lore Agent and MCP

Lore Agent는 앱 안의 대화형 작업 도우미이고, MCP는 같은 작업 기능을 외부 에이전트에 제공하는 접점이다. 에이전트의 추론 루프는 LangChain `create_agent`/LangGraph, 도구 입력은 Pydantic, 외부 프로토콜은 공식 MCP Python SDK를 사용한다. 애플리케이션 도구·승인·저장 규칙은 한 작업 계층에서 공유한다.

이 문서는 `dev`의 새 기능 구성 안내다. 소스에 기능이 있다는 것과 특정 배포에 패키지·인증·모델이 설정됐다는 것은 별도다. 실제 공급자 호출은 사용자가 선택한 BYOK 계정에 과금된다.

## 설치 프로필

기본 API 의존성은 유지하고 에이전트 프로필을 별도로 설치한다. API 디렉터리에서 격리된 가상환경을 사용한다.

```sh
python -m pip install --require-hashes --only-binary=:all: -r requirements-agent.txt
```

이 프로필은 기존 LangGraph/Core/LiteLLM 핀을 변경하지 않고 LangChain, 공식 MCP SDK, SQLite 체크포인터를 추가한다. `langchain[mcp]`, 별도 FastMCP 또는 `langchain-litellm`을 무조건 추가하지 않는다. 특히 `litellm`과 `litellm-core`는 동일한 Python 네임스페이스를 제공하므로 두 배포판을 겹쳐 설치하지 않는다. `pyproject.toml`의 `agent` extra는 기능별 직접 의존성을 설명하고, 배포에는 해시가 고정된 프로필을 사용한다.

## 기존 앱 접근 및 프로바이더 인증

앱 내부 설정·세션·승인은 기존 Lorechat 리소스 편집 화면과 같은 신뢰하는 단일 사용자·사설 네트워크 접근 방식을 사용한다. 별도의 소유자 키 생성, 서버 해시 설정, 잠금 해제 입력은 필요하지 않다. 공개 인터넷에 배포할 때는 기존 REST API 전체를 사설 네트워크 또는 별도 인증 프록시 뒤에 둔다. 이 기능이 로그인·멀티테넌트 인증을 대신하지 않는다.

모델 목록은 기존 프로바이더에 등록된 사용 가능한 모델에서 가져온다. API 키와 Vertex 인증 등은 기존 계정 설정을 서버에서 재사용하며, 에이전트 화면이나 외부 MCP에 공급자 자격 증명을 다시 전달하지 않는다. 역할극 모델과 별도로 에이전트용 모델을 선택할 수 있고, 기존 설정·초안·결과는 보존된다.

외부 MCP는 별도의 클라이언트별 Bearer 토큰과 권한을 유지한다. Bearer 자격 증명이 있는 요청은 내부 승인 REST 경로에서 거부하며 MCP 전용 경로를 사용한다. 모델 도구와 MCP 도구 목록에는 사용자 승인·이미지 방식 확정 기능이 없다. 기존 앱 접근이 가능한 네트워크 사용자는 기존 리소스 편집자와 같은 신뢰 대상이며, 이는 공개 네트워크의 강한 사용자 인증 경계가 아니다.

## 앱에서 사용

`설정 → 로어 에이전트`에서 다음을 설정한다.

- 에이전트 전체 사용 여부.
- 기존 등록된 에이전트용 프로바이더 계정과 그 계정의 LLM. 일반 역할극·압축·Decision·TTS 기본 모델과 별개다. 계정을 바꾸면 호환되지 않는 모델 선택을 비우며, 저장된 계정·모델은 임의로 바꾸지 않는다.
- 선택적인 이미지 계정·이미지 생성 모델. 이미지 입력을 받는 모델이라는 이유만으로 생성·참조 편집 모델로 취급하지 않는다.
- MCP 연동 사용 여부와 클라이언트별 권한.

이미지 모델이 없어도 글 작성·수정 기능은 사용할 수 있다. 내부 추론 모델을 설정하지 않은 외부 MCP 전용 사용도 구분한다. 외부 도구 호출이 내부 추론 모델을 불필요하게 다시 실행하지 않는다.

Agent가 켜져 있으면 모든 페이지에서 공통 버튼으로 접근한다. 넓은 화면에서는 보조 패널, 좁은 화면에서는 채팅 모달을 사용한다. 원래 페이지의 입력과 Agent 대화·초안은 서로 다른 상태다.

기본 화면은 메시지와 입력·전송 중심이다. 첫 메시지를 보낼 때 대화를 자동으로 만들므로 세션이나 ID를 먼저 선택할 필요가 없다. 이전 대화, ID를 이용한 복구, 참고 항목의 상세 제한은 접힌 고급 기능에서만 다룬다. 모델 미설정·진행 중 작업·전송 결과 확인이 필요한 상태에서는 막힌 이유를 입력창 근처에 표시한다. 결과가 불명확한 요청은 조회로 확인하며 유료 메시지를 자동으로 재전송하지 않는다.

일반 채팅에서는 도구가 작업과 관련된 캐릭터·세계관을 제한된 검색으로 찾고 필요한 작성 필드를 조회한다. 라이브러리 전체를 프롬프트에 자동 첨부하지 않으며 한 실행에서 최대 여덟 대상을 다룬다. 고급 기능에서 참고 항목·필드를 명시적으로 제한하면 그 범위는 계속 지킨다. 변경 저장과 유료 이미지 생성의 검토·승인은 별도다.

캐릭터·세계관 작업은 초안과 변경점을 검토한 뒤 저장한다. 이미지 작업은 모델·대상 종류(캐릭터/세계관)·프롬프트·개수·옵션을 확인하고 유료 생성을 승인한다. 생성 결과는 보존되며 미리보기 후 기존 캐릭터/세계관 목록에서 등록 대상을 선택한다. 생성만으로 기존 이미지를 덮거나 기본 프로필을 바꾸지 않는다.

캐릭터 이미지는 선택한 결과를 별도 승인 후 에셋으로 등록하며 기본 프로필을 자동 변경하지 않는다. 세계관 대표 이미지·배경 장면 생성은 같은 유료 승인 흐름을 사용한다. 결과 중 **한 장만** 선택하고 별도 등록 승인을 거치면 기존 세계관의 `thumbnail_url`만 교체한다. 세계관 갤러리나 채팅 배경 렌더러를 추가하는 기능이 아니다. 검토 이후 대상이 바뀌면 오래된 승인은 거부된다.

이미지 모델 목록과 참조 편집 지원 여부는 서버의 현재 허용 목록(`image_models`, `supports_reference`)을 따른다. 과거의 고정된 네 모델 목록이나 이미지 입력 지원만으로 편집 가능 여부를 판단하지 않는다. 처음 이미지 계정을 선택하거나 공급자를 바꿀 때 해당 공급자의 모델을 직접 선택한 뒤 저장한다.

### 기존 이미지의 외형 유지

이미 캐릭터나 세계관에 이미지가 있으면 **기존 외형 유지(참고 이미지)** 또는 **새 이미지 생성**을 소유자가 직접 선택한다. 기본 답변이나 최근 이미지 자동 선택은 없다. 외형 유지를 선택하면 이름과 미리보기로 참고 이미지를 고르고 선택을 확정한다. 이 선택은 소유자 전용 REST 작업이며 내부 모델·외부 MCP가 대신 승인할 수 없다. 이미지가 없는 대상은 일반 새 이미지 생성 흐름을 사용한다.

참고 미리보기는 소유자 헤더로 인증된 로컬 원본과 확정된 불변 스냅샷을 사용한다. 외부 URL이나 읽을 수 없는 이미지는 가져오지 않는다. 사용 가능한 로컬 에셋을 선택하거나 기존 캐릭터 에셋 화면에서 업로드한다. 선택 모델이 참조 편집을 지원하지 않으면 유료 실행을 막고 설정에서 명시적으로 모델을 변경하도록 안내한다. 모델·공급자·새 이미지 생성으로 자동 대체하지 않는다.

확정 후 생성 방식·모델·프롬프트·개수·참고 이미지를 검토하고 유료 생성을 별도로 승인한다. 프롬프트·선택·참고 이미지가 바뀌면 이전 승인은 사용할 수 없다. 참고 이미지는 외형 유지 지침이지 결과의 동일성을 보장하지 않는다. 생성 결과의 별도 에셋/세계관 등록 승인과 기존 프로필 보존 규칙은 그대로다. 브라우저 복구 저장소에는 요청 식별자만 저장하며 이미지·프롬프트·키는 저장하지 않는다.

## 외부 MCP 연결

- 전송: 공식 MCP SDK의 Streamable HTTP, stateless JSON 응답.
- API 직접 경로: `/mcp`.
- 웹의 기존 `/api` 프록시를 통하는 경로: `/api/mcp`.
- 인증: 클라이언트별 Bearer 토큰. 앱 설정에서 발급할 때 한 번만 표시된다.
- 공급자 키나 Vertex 자격 증명을 MCP 클라이언트에 전달하지 않는다.

사용하는 MCP 클라이언트의 HTTP 서버 설정에 배포 주소와 `Authorization: Bearer <client-token>` 헤더를 지정한다. 연결 설정 파일의 문법은 클라이언트마다 다르므로 각 클라이언트의 공식 형식을 따른다. 이 단계는 수동 Bearer 토큰 방식이며 OAuth 공급자·로그인·발견 URL을 흉내 내지 않는다. OAuth만 지원하는 클라이언트의 연결은 별도 인증 구성이 필요하다.

모든 MCP 연결에는 조회(`lore:read`)가 필수로 포함된다. 권한은 조회(`lore:read`), 초안(`lore:draft`), 승인된 저장(`lore:commit`), 승인된 이미지 생성(`lore:image:generate`)으로 구분한다. 도구 목록 표시나 토큰 소지만으로 인간 승인을 대체하지 않는다. 외부 에이전트는 승인 요청과 처리 결과 조회를 할 수 있지만 소유자 승인 도구는 제공하지 않는다. 클라이언트는 개별적으로 폐기할 수 있다.

MCP Host/Origin 허용 목록은 배포 환경에 맞게 명시한다.

```sh
export LORECHAT_MCP_ALLOWED_HOSTS='localhost:*,127.0.0.1:*'
export LORECHAT_MCP_ALLOWED_ORIGINS='http://localhost:5174'
```

외부 접근이 필요한 경우 실제 검증한 호스트·Origin만 추가한다. 운영 환경에는 HTTPS와 인증된 접근 경계를 사용한다. 공개 MCP 경로를 만들기 위해 기존 익명 REST API나 업로드 루트를 통째로 공개하지 않는다. 이 안내는 프록시·방화벽·인증 제공자를 자동으로 변경하지 않는다.

## 도구 확장 규칙

공유 도구 레지스트리에 이름, 설명, 엄격한 입력 스키마, 필요한 권한과 부수효과 정보를 등록한다. 내부 LangChain 도구와 MCP 도구가 같은 입력 검증·대상 범위·승인·중복 방지 규칙을 실행한다. 새로운 기능을 추가하기 위해 프로토콜 서버나 에이전트 추론 루프를 다시 만들지 않는다.

범용 SQL, 파일·셸, 브라우저 제어, 임의 HTTP, 공급자 키 관리 도구는 노출하지 않는다. 캐릭터·세계관·에셋 작업의 허용된 도메인 기능만 제공한다.

## 제품 지식과 초안 작성 지침

`app/agent/knowledge.py`의 정적 제품 안내를 표준 `create_agent`의 시스템 메시지에 붙여 **첫 모델 호출부터** 전달한다. 라이브러리·사용자 페르소나·공급자 키를 자동 수집하는 RAG나 별도 추론 루프가 아니다. `lore_capabilities`는 같은 안내와 허용 필드별 의미·값 형식을 반환하며, 생성 도구 설명은 같은 필드 안내에서 만든다. 내부 LangChain과 공식 MCP SDK가 공유 `ToolSpec` 설명과 기존 입력 스키마를 그대로 사용한다. 도구 추가나 강제 도구 선택은 없다.

- 실제 생성·수정 요청의 요구사항이 충분하면 `lore_stage_character` / `lore_stage_world`로 검토 가능한 초안을 만든다. 정규화된 미리보기를 확인하고 `lore_request_approval`로 검토를 요청한다. 일반론이나 일괄 질문만으로 끝내지 않도록 안내한다. 설명·아이디어 상담만 요청했다면 초안을 강제하지 않는다.
- 새 항목은 `target_id` 없이 작성한다. 수정은 제한된 검색과 필요한 필드 조회로 대상을 확인한 뒤 바뀐 필드만 전달한다. 대상 식별 등 중요한 모호함은 질문하고, 사소한 창작 선택은 되돌릴 수 있는 가정으로 제안하여 답변에 명시한다. 승인·이미지 방식·참조·모델 선택에는 이 재량을 적용하지 않는다.
- 세계관 `description`은 목록용 개요, `world_seed`는 지속되는 설정·규칙·기원, `opening_scene`은 첫 상황이다. `opening_line`은 방 생성 시 첫 캐릭터의 실제 발화로 들어갈 수 있다. 사용자 원문의 상세 설정을 짧은 개요로만 축약하지 않는다.
- 캐릭터는 `name`과 `persona`가 필수이며 외형·행동·말투와 목록형 감정/금지 규칙을 분리한다. `trait_scores`는 1–5 정수이며 서술을 대체하지 않는다. 세계관 생성에는 `title`이 필수다. 안내는 `CHARACTER_FIELDS` / `WORLD_FIELDS` 안의 필드만 광고한다.
- 대화방의 세계관은 선택 사항이다. 이 도구가 대화방·참여자를 생성하거나 연결한다고 주장하지 않는다. 초안·검토 요청은 저장 영수증이나 소유자 승인이 아니다. 이미지 선택·참조 스냅샷·유료 실행·별도 등록 승인과 자동 대체 금지는 기존 규칙을 유지한다.

근거는 `app/agent/contracts.py`, `app/schemas/characters.py`, `app/schemas/world_settings.py`, `app/services/conversation_service.py`, `app/services/world_setting_service.py`, `app/engine/prompts.py`와 웹 세계관 편집 화면이다. 필드나 소비 방식을 바꾸면 제품 안내와 `tests/agent_core/test_product_guidance.py`를 함께 갱신한다. 해당 테스트는 TCP 차단·격리 저장소에서 첫 요청의 안내/도구 설명, 합성 도구 호출→초안→검토 요청, 승인 없는 저장 거부, 상세 서술 보존, MCP 설명 일치를 검증한다. 이는 실제 모델의 창작 품질이나 반드시 도구를 선택한다는 보증이 아니다.

## 실패와 비용

- 결과가 불명확하면 원래 요청 식별자로 상태를 조회한다. 같은 유료 요청을 자동 재전송하지 않는다.
- 이미지 생성 성공 뒤 등록만 실패하면 보존된 결과로 등록을 재시도한다. 다시 생성하는 복구가 아니다.
- 검토 후 원본이 바뀌면 오래된 승인을 적용하지 않고 다시 비교한다.
- OFF는 새로운 Agent 도구·모델 작업을 막는다. 이미 공급자에 전송된 요청의 취소나 환불을 보장하지 않는다.
- 토큰·비용의 실제 보고치, 추정, 미상을 구분한다. 미상을 무료 또는 0원으로 표시하지 않는다.

격리된 합성 공급자 테스트는 프레임워크·입출력·승인·저장 규칙을 검증한다. 실제 공급자 인증과 유료 생성 품질 검증은 별도 허가가 필요한 단계다.

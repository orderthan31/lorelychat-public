# 이미지 표시 캐시와 삭제 정리

## 원본·저장 주소·화면 주소의 구분

기존 업로드 파일과 DB의 `image_url`, `thumbnail_url`, `avatar_url`은 일괄 변환하거나 덮어쓰지 않습니다. 새 에셋의 등록·교체 정규화 정책은 [Decision 에셋 문서](asset-decisions.ko.md)를 따릅니다. 화면 표시와 모델 입력은 원본과 별개의 파생 리소스입니다.

- 화면에서는 공통 `WebpImage`와 이미지 전용 `imageUrlFor`를 사용합니다. Home, 캐릭터·세계관·대화방 목록, 아바타, 캐릭터 카드, 방 정보, 버블 에셋, 에셋 갤러리, 편집/등록 미리보기, 큰 이미지 미리보기를 포함합니다.
- 브랜딩의 테마별 파일과 기본 별칭, favicon도 실제 WebP 파일을 제공합니다. 기존 PNG는 호환·원본 자료로 남지만 활성 화면 경로로 사용하지 않습니다.
- 일반 `assetUrlFor`는 오디오와 기존 다운로드/교환 계약을 위해 유지합니다. 작성한 URL 입력값에 파생 URL을 되써 넣지 않습니다.
- 아이콘·앱 내부의 data SVG·Lottie 벡터는 래스터 변환 대상이 아닙니다. URL의 `.svg` 확장자만으로 외부 이미지를 검증 없이 우회하지 않습니다. 지원하지 않는 외부 SVG는 변환 실패로 표시합니다. Markdown 이미지와 HTML을 새로 허용하지 않습니다.

## 표시 API

다음 경로 앞에는 웹의 `API_BASE`가 붙습니다.

- `GET /images/render.webp?source=...&variant=thumbnail|full`: 상대 `/uploads/` 이미지 경로만 허용합니다. 임의 외부 URL을 GET 쿼리로 받지 않습니다.
- `POST /images/prepare`: JSON의 `source`, `variant`로 외부 URL이나 base64 PNG/JPEG/WebP/GIF를 명시적으로 준비합니다. 성공 시 원본 URL 대신 불투명한 `/images/cache/.../*.webp` 주소를 반환합니다. URL의 비밀 쿼리는 이미지 요청 주소에 복사하지 않습니다.
- `GET /images/cache/{source_key}/{filename}`: 검증된 파생 이미지 바이트만 제공합니다. 메타데이터·원격 원본 스냅샷·lock·삭제 의도 파일을 제공하지 않습니다.

성공 응답은 이름만 바꾼 원본이 아닌 실제 `image/webp`입니다. `thumbnail`은 긴 변 최대 512px, `full`은 최대 2048px, 품질 설정은 80입니다. 허용된 입력의 애니메이션을 표시 파생본에서 보존합니다. 이미 정적인 저장 썸네일을 애니메이션으로 복원하지는 않습니다. 작은 이미지는 불필요하게 확대하지 않습니다.

이 표시 API의 파생본 응답은 ETag와 `private, max-age=0, must-revalidate`를 사용합니다. 원본을 직접 제공하는 기존 `/uploads/` 응답의 캐시 정책을 새로 바꾸지는 않습니다. 원본 파일의 교체·소실은 다음 로컬 해석 요청에서 확인합니다. 서버에서 삭제해도 이미 브라우저가 받아 현재 표시 중인 픽셀을 회수할 수는 없습니다.

## 지속 캐시와 모델 전송

파생본은 소유 업로드 root 내부의 비공개 `.image-cache/v1`에 저장합니다. 캐시 키는 입력 내용의 SHA-256, 출력 MIME, 해상도·padding·품질·애니메이션 옵션, 변환 정책 버전을 포함합니다. 같은 파일과 같은 옵션이면 다시 인코딩하지 않습니다. 입력 바이트나 옵션이 달라지면 새 결과를 만들고 해당 소스의 오래된 내용 세대는 정리합니다.

프로세스 간 source flock을 원본 읽기 전부터 검증·원자적 발행까지 유지합니다. 삭제 정리도 같은 소스 lock을 사용합니다. 부분 파일은 성공 결과로 취급하지 않으며 캐시 손상 시 다시 생성합니다. lock anchor는 기다리는 프로세스가 있을 수 있으므로 임의로 삭제하지 않습니다.

Decision도 이 서비스를 사용하지만 화면용과 입력 정책은 분리됩니다.

- 지원 능력이 확인되지 않았거나 텍스트 전용인 경로는 이미지 파일을 읽지 않습니다.
- 개인 소유 원본만 확인하며, 화면이 공유 저장소에서 미리 만든 캐시가 있어도 이 검증을 우회하지 않습니다. 외부 이미지를 Decision 준비 과정에서 내려받지 않습니다.
- Google용 WebP와 Jev용 정적 baseline JPEG/PNG 등 실제 경로의 허용 MIME·padding 옵션에 맞는 파생본을 각각 재사용합니다.
- 기존 최대 8장, 장당 256KiB, 합계 1MiB, 준비 기한 3초를 유지합니다. 실패 시 같은 모델의 텍스트 선택 경로를 사용합니다. OFF의 기존 추천·빈도를 바꾸지 않습니다.

## 외부 URL과 제한

외부 URL의 수집은 기존 DNS/IP 고정, 전역 주소 검증, redirect 재검증, 스트리밍 크기·시간 상한을 재사용합니다. 지원되지 않는 주소·형식, 차단된 주소, 기한 초과에 원본 PNG/JPEG 주소를 그대로 렌더하는 숨은 fallback은 없습니다. 이미지 영역의 대체 텍스트와 도움말에 한국어·영어·일본어의 불러오기 실패를 표시합니다.

상대 업로드 경로, 현재 앱/API 호스트, 과거 loopback 앱 업로드 주소는 로컬 표시 주소로 해석합니다. 제3자 공개 호스트에 우연히 `/uploads/` 경로가 있어도 개인 파일 경로로 바꾸지 않습니다. 알 수 없는 과거 외부 호스트의 주소는 명시적 외부 준비 경로를 거칩니다.

주요 상한은 다음과 같습니다.

- 입력/출력 이미지 각 8MiB, 최대 변 2048px. base64를 담는 POST JSON 전체는 10MiB이므로 base64 오버헤드까지 포함한 더 작은 실효 입력 상한이 적용됩니다.
- 캐시 소스/lock 구획 4,096개, 소스당 파생 규격 16개·24MiB, 전체 파생 이미지 8,192개·256MiB. 원본 파일 용량은 이 파생 캐시 한도와 별개입니다.
- 원격 원본 스냅샷의 재사용 TTL은 30초입니다. 원본 URL/쿼리는 스냅샷 메타데이터에 저장하지 않습니다.
- 웹의 준비 요청 memo는 최대 128개, 동시 준비 32개, 키 문자열 합계 제한을 사용합니다. 성공 결과는 5분, 실패 결과는 10초 뒤 재사용 기간이 끝납니다. 준비 대기는 15초, 이미지 로드는 20초로 제한합니다. 화면에 계속 떠 있는 이미지를 주기적으로 다시 가져오는 polling은 아닙니다.
- 서비스의 요청은 최대 30초, async lock·decoder 입장 대기는 각각 최대 15초이며 Decision의 별도 3초 기한이 우선합니다.

무제한 영구 캐시나 전역 LRU를 제공하지 않습니다. 고정 anchor나 용량 상한을 넘으면 새 발행을 거절하며 원본을 삭제하거나 원래 형식으로 우회하지 않습니다. 캐시를 수동 정리할 때는 생산자·대기자가 모두 종료된 상태가 필요합니다. 실행 중 lock 파일을 지워 용량을 확보하지 않아야 합니다.

첫 표시에는 변환 비용이 생길 수 있습니다. 이후 동일 파생본을 재사용하지만 모든 이미지에서 파일 크기·로드 지연·모델 토큰이 일정 비율로 줄어든다는 보장은 없습니다.

## 에셋 삭제

DB 삭제의 성공이 확인된 다음, 남은 참조를 다시 확인하고 참조 없는 개인 소유 이미지·썸네일과 그 파생 캐시를 정리합니다. 다른 에셋, 아바타, 세계관/과거 방 이미지, 작성된 텍스트·JSON이 같은 파일을 참조하면 보존합니다. 기본 에셋을 삭제해도 캐릭터 아바타가 그 이미지를 계속 참조하면 원본은 남고, 해당 에셋만 쓰던 썸네일은 정리할 수 있습니다.

공유 root의 파일과 에셋 등록에 입력으로만 사용했던 별도 원본을 일괄 삭제하지 않습니다. 소유 여부가 불명확한 외부 주소를 근거로 같은 이름의 개인 파일을 지우지 않습니다. 참조 검사와 파일 정리는 실제 SQLite 쓰기 예약 및 source lock 안에서 수행합니다. 이 검사는 참조를 조회한 순간 이후의 경쟁 commit과 진행 중인 파생 생성도 다룹니다.

삭제 의도는 비공개 `.image-cleanup` journal에 DB commit 전에 남깁니다. 활성 요청은 ticket lock을 commit까지 보유하고, 실패·프로세스 종료 후에는 DB의 실제 상태와 참조를 확인해 재시도합니다. 취소된 삭제나 불명확한 소유 상태에서는 보존을 우선합니다. 재시도는 시작 시와 이후 에셋 삭제 시 제한된 수만 처리하며, 별도 cron이나 DB 스키마 변경을 요구하지 않습니다. 파일 정리가 늦어져도 이미 commit된 DB 삭제를 가짜 rollback으로 보고하지 않습니다.

두 비공개 제어 디렉터리는 직접 `/uploads/` 요청과 symlink 별칭을 통한 정적 제공에서 제외합니다. 미디어 원본의 orphan 조사에서도 캐시·journal을 원본 고아 파일로 집계하지 않습니다. 이 기능은 기존 전체 업로드의 자동 고아 삭제나 캐릭터/방/세계관 삭제 정책 변경은 아닙니다.

## 검증 경계

코덱·캐시·API·DB 참조·프로세스 간 lock·브라우저는 합성 이미지와 격리된 저장소/DB로 검증합니다. 이러한 결과는 유료 provider의 실제 품질·비용·지연이나 운영 활성화를 뜻하지 않습니다. 운영 데이터에 대한 파생본 일괄 생성, 파괴적 마이그레이션, 설정의 자동 ON 전환은 하지 않습니다.
